## 1. What this is

A field-prospecting map for **Conor Kain**, a sales rep at **The Chefs' Warehouse**
(specialty / center-of-plate food distributor) covering **Westchester County, NY**.
He uses it to decide who to call on and when.

- **Live:** <https://ckaiin.github.io/prospect-heatmap/>
- **Repo:** `ckaiin/prospect-heatmap` (public) · **Local:** `/Users/conorkain/prospect-heatmap/`
- **Deploy:** push to `main` → GitHub Pages builds automatically. No build step.

**Who counts as a prospect** matters for scoring changes. Chefs' Warehouse targets
**wide**, not just white-tablecloth: fine dining, country clubs, hotels/caterers,
pastry/bakeries/chocolatiers (an underserved sweet spot), and **fast-casual — the
biggest growth segment**. The only clear non-fit is **national/regional chains**
(they buy centrally, a rep can't win them) and commodity broadline buyers. Note
fast *food* is excluded but fast-*casual* is a target; they are different things.
The authoritative brief is `~/Downloads/life-os-repo/docs/WORK-PORTFOLIO.md` §4/§6.

## 2. Running it

```bash
cd ~/prospect-heatmap
python3 -m http.server 8899        # then open http://localhost:8899/index.html
node test_sync.js                  # the only unit tests (tracker merge)
```

There is no bundler, no package.json, no install step. `index.html` is the whole
app; everything else is generated data or a build script.

**Syntax-check the inline app code** (it's ~700 lines inside `index.html`):

```bash
python3 - <<'EOF'
h=open('index.html').read(); s=h.rindex('<script>'); e=h.index('</script>',s)
open('/tmp/app.js','w').write(h[s+8:e])
EOF
node --check /tmp/app.js
```

## 4. How the data fits together

```
overpass_raw.json ──build_data.py──► restaurants.js ─┐
                        ▲                            │
NY SLA API ──openings_feed.py───────► openings.js ───┼──► window.PROSPECTS
                        ▲                            │      (index.html)
                     fit.py                          │
                                                     │
.briefsrc/*.json ──build_briefings.py─► briefings.js ┘
```

`PROSPECTS` = restaurants + openings, merged at load. Tracker state
(status/notes) is overlaid on top from localStorage, then from Supabase if
configured.

**Real vs. simulated** — be careful not to present simulated data as real:

| Field | Status |
|---|---|
| name, category, cuisine, street, lat/lng, hours | **Real** (OpenStreetMap) |
| openings (name, address, license stage, dates) | **Real** (NY State Liquor Authority) |
| briefing content + sources | **Real** (researched, with per-source credibility) |
| `fitScore` | Real heuristic (`fit.py`), not a model |
| **popular-times curves** | **Modeled**, not observed — see §6 |
| `status` | Starts `"new"` for everything |
| `monthlyValue` | **Placeholder.** Never modelled. Don't build on it |

## 5. Landmines

These all cost real time to find. Read before debugging.

**Browser caches `briefings.js` / `openings.js` hard.** You will rebuild data
locally, reload, see no change, and conclude your code is broken. It isn't — a
normal reload isn't enough, you need **cmd+shift+R**. GitHub Pages is fine
(commit-based ETags); this only bites local testing.

**Importing `openings_feed.py` executes it.** It's a script, not a module — a
bare `from openings_feed import nice_name` runs the whole feed and **overwrites
`openings.js`**. I did exactly this and clobbered 137 openings down to 76.
`git checkout -- openings.js` restores it. To reuse a function, `exec` just the
slice you need.

**A venue's SLA id changes when it opens.** Pending licenses are `sla-NA-…`;
once issued they become `sla-active-…`. Briefings are keyed by id, so a venue
graduating from "opening soon" to "just opened" used to silently lose its
researched briefing. Fixed by also keying on normalized name+address, with an
address-only fallback when that address maps to exactly one briefing (labeled
"matched by address" in the popup). `.briefsrc/_venues.json` is the persistent
id → name/street registry that makes rolled-off ids still resolve — **deleting it
breaks recovery of every past briefing.**

**Openings age out; stale briefings accumulate.** The "recently opened" window is
60 days, so `briefings.js` will always have more entries than `openings.js`.
Expected, harmless.

**A dead CDN dependency failed silently for weeks.** `opening_hours`'s
`+deps.min.js` bundle was removed upstream and that URL 404s, so the parser never
loaded, every hours feature degraded to "unknown", and the Open now / Closed now
filters matched **zero** venues while looking merely empty. Now loads `suncalc` +
`opening_hours@3.14/build/opening_hours.js` (UMD, reads SunCalc off the global)
and logs `[heatmap]` if the parser is ever missing. **If hours features look
"unknown" everywhere, check this first.**

**Everything fails toward "still usable".** That's deliberate for a tool used in
the field, but it means bugs present as *missing features*, not errors. The sync
layer logs `[sync]` warnings on every failure path. Check the console early.

**No Docker or Supabase CLI on this machine**, so the Edge Functions could not be
run locally. They are untested until deployed.

## 6. Design decisions worth not re-litigating

**Google Popular Times is not scraped, deliberately.** Conor asked, and waived
the ToS concern; I still declined and he accepted the alternative. Beyond terms:
it's an undocumented endpoint requiring session tokens, it blocks datacenter IPs
(i.e. any GitHub Action or cheap VPS), and it needs a headless browser per venue,
so it breaks every few months. Across 868 venues weekly that's a permanent
maintenance burden. **BestTime.app** is wired up instead — licensed, same signal,
key lives server-side.

**Popular-times curves are modeled and must stay labeled as such.** Per-category
daypart curve × cuisine nudge × day-of-week, clipped to real OSM hours where
known (~30% of venues). The UI says "Estimated from venue type…, not observed
foot traffic" and switches to "Real foot-traffic forecast (BestTime)" only when
the backend returns one. **Don't quietly drop that disclaimer.**

**The chart's read is inverted from Google's.** A tall bar is a *bad* time to
walk in. Recommendations are restricted to callable hours (9am–7pm) — an empty
dinner house at 7am is quiet but useless to a rep.

**Status color never carries meaning alone.** The obvious green-good/red-avoid
coding **fails** colorblind separation (validated: CVD ΔE 4.1, deuteranopes can't
distinguish them). Bar height carries busyness and the window is named in text;
green is reinforcement only. If you add status coding elsewhere, run
`scripts/validate_palette.js` from the `dataviz` skill rather than eyeballing it.

**Sync is offline-first because of where it's used.** Westchester cell coverage is
patchy and visits get logged in the field. localStorage is the source of truth for
every write; the UI never blocks on the network; the cloud is a replica that
catches up. Merge is last-write-wins per venue, ties keep local (a lost note is
worse than a lost keystroke).

## 7. State of the backend

**Code is written and pushed. The Supabase project does not exist yet** — Conor
has to create it. Until then the placeholders in `sbconfig.js` keep everything
inert and the map behaves exactly as it did before the backend existed.

Setup is four steps in **`supabase/README.md`** (~10 minutes for the sync
feature). Free tier, $0 at this scale.

| Piece | Status |
|---|---|
| `schema.sql` | Written, **not applied** |
| `sync.js` + UI | Written, **tested** (merge unit-tested; offline/failure paths exercised in-browser) |
| `functions/refresh-openings` | Written, **untested** — port verified identical to the Python on a 12-name fixture, upstream APIs confirmed live |
| `functions/foot-traffic` | Written, **untested** — needs a BestTime key |

Cutover notes:
- `refresh-openings` refuses to write when the feed returns 0 rows, so a bad run
  is a no-op rather than a wiped table. Treat the first deploy as the real test.
- Keep `openings_feed.py`. It's the reference implementation; if the port and the
  Python ever disagree, **the Python is right.**
- `monthly_value` uses SHA-256 in TS (WebCrypto has no md5), so those placeholder
  numbers shift once on cutover. They were never modelled — don't chase it.
- Only retire `.github/workflows/refresh-openings.yml` after a confirmed
  successful cron run.

## 9. Conventions

- **Comments explain *why*, not *what*.** Match the existing density — the code
  is commented for someone returning in six months, not for a tutorial.
- **No dependencies without a reason.** No build step, no framework. New runtime
  deps are CDN `<script>` tags, and they must degrade gracefully — see the
  `opening_hours` landmine for what happens when one dies silently.
- **Everything optional must work when absent.** Briefings, hours, sync, real
  foot traffic are each independently skippable.
- **Don't present modeled data as observed.** The map's credibility with its one
  user is the whole point.
